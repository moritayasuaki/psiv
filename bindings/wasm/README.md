# @psiv/experimental

Rust-backed PSIV for Node.js and browsers. Local package only; not published. Packaged builds include WebAssembly, ES modules and TypeScript declarations. Git clones contain source and loaders; run `./scripts/build.sh` from the project root to generate the WASM module first. Research software: no Rust/Lean equivalence, compiled constant-time or production-security guarantee.

Install the tarball from `releases/packages/`, generated by `scripts/package.sh`, with `npm install /path/to/psiv-experimental-0.5.0-experimental.tgz`, or import `node.mjs` directly from this directory. Node selects the local-file loader automatically through package exports.

```js
import {createSession} from '@psiv/experimental';
// Public test values. Applications must provide their secret key and nonce.
const key = new Uint8Array(32);
const nonce = new Uint8Array(12);
const ad = new TextEncoder().encode('header');
const session = await createSession(key);
try {
  const record = session.seal(nonce, ad, new TextEncoder().encode('hello'));
  const plaintext = session.open(nonce, ad, record);
  console.log(new TextDecoder().decode(plaintext));
} finally {
  session.destroy();
  key.fill(0);
}
```

For direct browser use, serve this whole directory over HTTP(S) and import `./browser.mjs`. Its loader fetches `generated/psiv_wasm_bg.wasm` relative to the module. Serve WASM as `application/wasm`; configure the application's CSP to permit WebAssembly. Bundlers must preserve or copy that relative asset. The explicit package export `@psiv/experimental/browser` is also available.

`createSession` copies the 32-byte key before its first await. Calls accept `Uint8Array`; nonce is exactly 12 bytes, AD and plaintext each at most 65,536 bytes. `seal` returns ciphertext || 16-byte tag. `open` throws on authentication failure and returns no candidate plaintext. Inputs remain unchanged and outputs are separately owned arrays. `destroy()` is idempotent; calls after destruction fail. Manage caller-owned keys and plaintext explicitly. JavaScript, browser engines and WASM allocators are not covered by a formal erasure or timing proof.
